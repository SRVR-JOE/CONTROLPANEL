1. INTRODUCTION
As of version 3.1.0 Tessera processors support remote query and control/triggering functionality over a variety of IP-based protocols via a filesystem-like, RESTful API. This document describes how to access the information available and the format in which it is presented. The API currently focuses on functionality needed for runtime control of the processor, it does not seek to offer all functions of the processor UI. More functionality will be added in future releases. In order to use IP control it must be enabled in the Live Control tile in the processor user interface. The processor on the client must be on the same network and have a compatible IP address configuration.

PROCESSOR SETUP
IP control must be enabled within the project file in order to function, this is done from the control tile in the processor UI. Please refer to the Tessera User Manual for more information.
CONTROL DEVICE SETUP
Make sure that your control device (e.g. laptop) is set to an IP range in the same subnet as the processor, and is physically connected to the same network as your processor's management port. For the purposes of this document, we will be using the factory default IP address of a Brompton processor, 192.168.0.50. Be sure to replace this IP address with that of your processor.
POLLING
Many IP based control systems are set up to 'poll' the target device at fixed intervals to retrieve and update information about that device. Polling the processor has a 'cost' to retrieve the information requested, both for the client (e.g. the laptop sending the API request) and host (e.g. the processor). Consider how often you need to update the information, and the scope of the information you need. Polling large amounts of data multiple times per second may cause adverse performance issues with your processor, so is generally unadvised.

2. API
DATA TYPES
The following endpoint data types are supported:
string: text string of up to 128 UTF-8 encoded characters bool: boolean state, true or false integer: signed 16-bit integer, range -32768 to 32767 float: floating point value bytearray: array of bytes containing binary data enum: string enumeration representing one of a discrete set of possible values testpatterntype: either an enum representing a test pattern, or an integer representing a frame store image by its user number.
COMMANDS
get: get one or more endpoints' value(s) set: set an endpoint or group of endpoints' value(s) list: show a summary of available endpoints starting from any position in the API tree help: show help text for an endpoint or directory detailing what the endpoint represents, access specifier, data format and range
Examples of each command are given in the protocol section.
ACCESS SPECIFIERS
The following access specifiers are supported:
R/W: the endpoint is both readable and writable R/O: the endpoint is read-only and may not be written to W/O: the endpoint is write-only and may not be read
ERRORS
The following errors may be returned as the result of a command operation:
Path not found: the requested endpoint path was not recognised Bad operation: operation was not valid, e.g. trying to set a read-only endpoint Not supported: not supported by the hardware platform or not yet implemented Missing input parameter: required input parameters are missing or malformed Bad input parameter type: one of the input parameters had an incorrect type or format Bad input parameter value: one of the input parameters had an invalid/out of range value Access denied: insufficient privilege level for the requested operation No project loaded: the target processor does not have a project loaded Object not found: the requested object (e.g. panel) was not found Operation failed: general runtime failure

4. PROTOCOL EXAMPLE USAGE
HTTP
IP Control functionality over HTTP on port 80 is accessed via the /api path root to distinguish it from other web services.
http://192.168.0.50/api/
All commands are accessible via the regular HTTP verbs GET (for read, list and help operations) and PUT (for set). There is also query-parameter based support for accessing all operations exclusively via GET for older clients that do not support extra verbs.
A successful HTTP request will return the value of the parameter that has been requested, including the new value if a write command is issued. For example: {"brightness":1000}.
An unsuccessful HTTP request will return the response code string and any error messages generated by the API, for example: {"response-code":"Path not found"}.
READING DATA
Use GET verb with target path. Example to get input video refresh rate:
Client: GET http://192.168.0.50/api/input/active/refresh-rate
Server: HTTP/1.1 200 OK Content-Type: application/json { refresh-rate: 60 }
WRITING DATA
Use PUT verb including data to set in a "data" tag in a JSON body. Example to set output brightness:
Client: PUT http://192.168.0.50/api/output/global-colour/brightness Content-Type: application/json { "data": 5000 }
Server: HTTP/1.1 200 OK Content-Type: application/json { "brightness": 5000 }
Alternative using GET verb only: pass the value to set as a "set=" query parameter.
Client: GET http://192.168.0.50/api/output/global-colour/brightness?set=5000

Use GET verb passing "help=1" as a query parameter
Client: GET http://192.168.0.50/api/override?help=1

SETTING MULTIPLE ENDPOINTS
It is possible to query and set multiple endpoints using the same command. This method requires fewer calls to the API (is more efficient), and is generally advised when attempting to make a number of changes to the processor at the same time.
WITH GET REQUEST
It is possible to chain multiple commands in a basic GET request, by adding ?set=1 after the API path, and chaining multiple parameter/value pairs with the & symbol. Example: to set a processor's active video input to the first SDI port, two commands are required.
http://192.168.0.50/api/input/active/source/port-type?set=sdi http://192.168.0.50/api/input/active/source/port-number?set=1
We can combine these two commands into a single GET request.
http://192.168.0.50/api/input/active/source?set=1&port-type=sdi&port-number=1

WITH PUT REQUEST VIA JSON
Where a large number of parameters should be set at the same time, it may be preferable to use a PUT request, with the body of request containing the parameter/value pairs formatted as JSON. Example: to set a processor's Output Brightness, Colour Temperature, and Output Colour Gains at the same time, we can format this into a single PUT request.
PUT http://192.168.0.50/api/output/global-colour Content-type: application/JSON {
"data": { "brightness": 4000, "colour-temperature": 5600, "gains": { "blue": 200, "green": 200, "intensity": 200, "red": 97.8, }
} }
PASSING AN ARRAY OF VALUES INTO JSON
Some endpoints, such as specifying which frames to enable Hidden Markers on, require an array of values. This requires careful formatting using correct JSON notation Example: to enable Hidden Markers on frames 2 and 4 on a processor, the following PUT request can be used.
PUT http://192.168.0.50/api/output/network/hidden-markers/frames-enabled-on Content-type: application/JSON {
"data" : { "frames-enabled-on": [ 2, 4 ]
} }

TELNET/TCP SOCKET
Telnet is a client/server protocol used for bi-directional communication across a network using TCP port 23. Telnet is case- and whitespace-sensitive, so commands will need to be entered exactly as written. If working inside a Telnet terminal window, delete and backspace often do not work, so careful typing is required. Alternatively, write the command out in full in a text editor, then copy and paste into your Telnet terminal.
WINDOWS
You may have to enable Telnet on Windows if you have not previously done so. One method of doing this is
Open Command Prompt (right-click, Run as Administrator) dism /online /Enable-Feature /FeatureName:TelnetClient Close and re-open Command Prompt
To connect to a processor, open Command Prompt and enter telnet 192.168.0.50 23. In the new Telnet window that opens, you can send now Telnet commands to the processor. As noted above, it may be helpful to write out commands in a separate text editor. To paste a command into the Telnet terminal, right-click on the terminal window.
To set an endpoint: set path/to/endpoint/n-1/ endpoint=value Example: set output/global-colour/ brightness=1000
When an endpoint has been set successfully, telnet will return the API tree from /n-1/.
To get an endpoint: get path/to/endpoint/ . Example: get output/global-colour/brightness will return brightness=1000 .
MACOS
To use Telnet in the macOS terminal, Telnet must first be installed on the system. One recommended installation method is using homebrew package manager. If homebrew isn't already installed on the control device (e.g. laptop), see the homebrew documentation for installation instructions. To install Telnet, open the Terminal, and use the command brew install telnet . Once Telnet has been installed, follow the instructions for using Telnet on Windows to connect and control your processor.

TESTPATTERNTYPE
Either an enum representing a test pattern, or an integer representing a frame store image by its user number. Used for Test Pattern Type endpoint. To set Test Pattern Type to one of the available test patterns, use one of the enums from the documentation (e.g. colour-bars). To recall a Frame Store, use the corresponding user number. See notes and examples for Enum and Integer data types.
